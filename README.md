# MSP430 Легаси-BSL: набор утилит

Инструменты для реанимации и прошивания MSP430 семейства 1xx (проверено на **MSP430F1611**, BSL 1.61)
через UART-загрузчик (Bootstrap Loader) без отладчика. Работают поверх Win32 API через `ctypes`,
внешних зависимостей не требуют — только стандартная библиотека Python 3.
Кроссплатформенность: код порта рассчитан на Windows; под Linux понадобится замена слоя `open_port`/
`set_lines` на `termios`/`serial` (приветствуется `pyserial`).

---

## Состав

| Файл | Назначение |
|---|---|
| `bsl_core.py` | Общий модуль: порт, протокол BSL, чтение/запись/стирание. Его импортируют все скрипты |
| `bsl_version.py` | Проверка связи: вход в BSL, чтение версии загрузчика |
| `bsl_read.py` | Чтение: Info-память, векторы прерываний, полный дамп флеша в файл |
| `bsl_write.py` | Запись: заливка образа (bin / Intel HEX) с проверкой каждого блока, запись Info |
| `bsl_erase.py` | Стирание: Mass Erase, флеш+Info B, отдельные сегменты, с верификацией чтением |
| `compare.py` | Побайтовое сравнение дампа чипа с образом прошивки (независимая верификация) |
Все основные скрипты лежат в одной папке вместе с `bsl_core.py`.

---

## Требования и установка

- Python 3.8+ (использовались f-string-совместимые конструкции, только стандартная библиотека).
- Windows 10/11, COM-порт (реальный или USB-UART адаптер).
- Адаптер подключён к чипу:
  - `TX` → `RXD` чипа, `RX` → `TXD` чипа;
  - `DTR` → `RST` (через схему входа BSL), `RTS` → `TEST` (TCK).
  - Для конкретной платы полярность может требовать инверсии — в этом наборе
    инверсия включается флагами `--inv-rst` и `--inv-test` (в нашем случае — оба).

Проверка связи за 5 секунд:

```
python bsl_version.py COM16 --inv-rst --inv-test
```

Ожидаемый ответ:

```
BSL version: 1.61, семейство: 0xF1 0x6C
```

`0xF1 0x6C` — семейство MSP430 1xx; если печатается другое — см. «Диагностика».

## Общие параметры (все скрипты)

| Флаг | Значение по умолчанию | Описание |
|---|---|---|
| `port` | — (обязателен) | Имя COM-порта, например `COM16` |
| `--inv-rst` | выкл | Инвертировать полярность DTR (линия RST) |
| `--inv-test` | выкл | Инвертировать полярность RTS (линия TEST) |
| `--trace` | выкл | Печатать каждый байт протокола и уровни DTR/RTS — основной инструмент диагностики |
| `--gap SEC` | `0.01` | Пауза между байтами фрейма. Если канал капризный — ставьте `0.05` |
| `--slow SEC` | `0.02` | Пауза между шагами входной последовательности BSL |

Скорость фиксирвана: **9600 бод, 8N1 с Even Parity** — так требует легаси-BSL 1xx (SLAU319C).

## Пароли: самое важное правило

Пароль легаси-BSL — это 32 байта из таблицы векторов прерываний `0xFFE0..0xFFFF`:
у пустого (стерёного) чипа это `FF`×32, у чипа с прошивкой — содержимое векторов
(в нашем образе: `3f 60 7f c3 ff ff ff ff ff c6 ff ff ff cc 3f ff ff ff ff ff 7c c3 ff ff 06 60 …`).

**Ключевое правило протокола:** одна неудачная попытка пароля (NAK) =
`mass erase` всей памяти. Поэтому во всех скриптах реализована стратегия
кандидатов (`password_candidates` в `bsl_core.py`):

1. **Первым пробуется пароль из образа** (если он указан и векторы непусты) —
   для чипа с уже залитой прошивкой он даёт ACK **без стираний**.
2. Если NAK (значит флеш был стёрт или не совпал — а NAK при этом сам сотрёт флеш),
   следующим пробуется `FF`×32 — на чистом флеше он всегда даёт ACK.

> **Никогда не запускайте операции, пока не понимаете, что в чипе сейчас лежит.**
> Если чип с прошивкой, а вы шлёте `FF`×32 первым — вы её сотрёте. Скрипты делают
> это безопасно сами, но при ручной работе через GUI (BSL430.NET и т.п.) помните:
> пустой или неверный пароль там = авто-стирание без предупреждений.

Сегмент **Info A (0x1000..0x107F)** с заводскими калибровками DCO защищён на уровне BSL
1.61: Mass Erase и ошибки пароля его не затрагивают. Остальные сегменты Info B (0x1080..0x10FF)
и Info C/D стираются и записываются штатно.

## bsl_version.py — проверка связи

```
python bsl_version.py COM16 --inv-rst --inv-test [--trace] [--gap SEC]
```

Выполняет входную последовательность, SYNC, читает версию BSL. Самый безопасный скрипт —
ничего не изменяет в памяти. Используйте первым при любых проблемах.

---

## bsl_read.py — чтение памяти

```
python bsl_read.py COM16 --inv-rst --inv-test [опции]
```

| Опция | Описание |
|---|---|
| `--pwfile FILE` | Файл образа, из которого берётся пароль (последние 32 байта). Рекомендуется всегда |
| `--password HEX` | Пароль вручную, 64 hex-символа (альтернатива `--pwfile`) |
| `--dump` | Прочитать весь основной флеш 0x4000..0xFFFF и сохранить в `flash_dump.bin` |
| `--gap`, `--trace`, `--slow`, `--inv-*` | общие |

Что делает:

1. Входит в BSL, проверяет версию.
2. Разблокируется паролем-кандидатами (см. правило выше).
3. Читает Info-память (0x1000..0x10FF) → `info_a.bin` (имя историческое, там весь Info).
4. Читает векторы прерываний (0xFFE0..0xFFFF) и печатает hex-строкой.
5. С `--dump` — читает основной флеш блоками по 128 байт **с прогрессом каждые 16 блоков**
   (48 КБ занимает ~1–1.5 мин при `--gap 0.01`; при `--gap 0.05` — до 4 минут,
   прогресс печатается, чтобы не казалось, что скрипт завис).

Чтение никогда не изменяет память — можно запускать сколько угодно раз.

## bsl_write.py — запись прошивки

```
python bsl_write.py COM16 --inv-rst --inv-test FILE [опции]
```

`FILE` — образ: сырой `.bin` (0x0000..0xFFFF, размер 65536) или Intel HEX (`.hex`).

| Опция | Описание |
|---|---|
| `--write-info` | Дописать в Info-память (0x1000..0x10FF) данные из образа. Основной флеш не трогается: пустые блоки пропускаются |
| `--gap`, `--trace`, `--slow`, `--inv-*` | общие |

Что делает:

1. Загружает образ (`load_image` поддерживает bin и Intel HEX).
2. Входит в BSL, проверяет версию.
3. Разблокируется паролем-кандидатами: сначала векторы из образа (безопасно для
   чипа с прошивкой), затем `FF`×32.
4. Пишет Info (если `--write-info`) и основной флеш блоками по 256 байт.
   Пустые (`FF`×256) блоки пропускаются — экономит ~2/3 времени (наш пример: 162 блока за 75 с).
5. **Каждый записанный блок читается обратно и сверяется** — при несовпадении блок
   перезаписывается (до 3 попыток), затем цикл стирания сегмента и повтор.
6. Финальный контроль: чтение векторов 0xFFE0..0xFFFF и печать hex-строкой.
   Векторы должны совпасть с образом — это главный маркер успеха.

> Не прерывайте скрипт посреди записи (Ctrl+C) — получите частично записанный флеш.
> Это не страшно: повторный запуск всё перезальёт, но имейте в виду.

## bsl_erase.py — стирание

```
python bsl_erase.py COM16 --inv-rst --inv-test [режим] [опции]
```

| Опция | Описание |
|---|---|
| (без режима) | Mass Erase основного флеша (команда 0x18, слово 0xA506) |
| `--all` | Mass Erase флеша **+ Info B** (слово 0xA505). Info A не трогается в любом случае |
| `--segment ADDR` | Стереть один сегмент по адресу. Можно несколько раз. Адрес выравнивается: 512 байт во флеше, 128 байт в Info (0x1000..0x10FF) |
| `--no-verify` | Не читать память после стирания (не рекомендуется) |
| `--yes` | Без интерактивного подтверждения |

Что делает:

1. Печатает предупреждение и ждёт «да»/`yes` (защита от случайного запуска).
2. Входит в BSL, проверяет версию.
3. Для `--segment` — сначала разблокируется (пароль из `FF`×32; NAK сам сотрёт флеш,
   что при стирании сегмента не страшно, но знайте).
4. Для Mass Erase команда шлётся **без пароля** — разрешена даже на защищённом BSL.
5. Шлёт команду стирания. Выводит ответ, честно предупреждая: у BSL 1.60+
   NAK после стирания может означать и успех (известный глюк erase check).
6. **Истина проверяется чтением**: скрипт читает стёртые области и добивается
   «все FF». При `--segment` читает только конкретные сегменты, при Mass Erase — весь флеш.

После стирания пароль чипа становится `FF`×32 — заливайте прошивку сразу:

```
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin
```

> **ВНИМАНИЕ.** Стирание безвозвратно удаляет прошивку. Запускайте только когда
> готовы к этому. Скрипт намеренно требует подтверждения — не отключайте его флагом
> `--yes` в автоматизации, если не уверены в аргументах на 100 %.

## compare.py — независимая верификация

Сравнивает дамп, снятый через BSL, с исходным образом. Прямое сравнение целых файлов
не сработает (`firmware.bin` — 64 КБ, а в дампе только области 0x4000..0xFFFF и Info),
поэтому сравниваются соответствующие срезы:

```
python compare.py
```

Ожидаемый вывод:

```
Основной флеш 0x4000..0xFFFF: OK — побайтово совпадает (49152 байт)
Info-память 0x1000..0x10FF: OK — побайтово совпадает (256 байт)
```

Если есть различия — печатает адреса первых 10 несовпадений. Это полноценная
независимая верификация: чтение идёт другим сеансом BSL, другим скриптом, чем запись.

## Типовые сценарии

### Реанимация «мёртвого» чипа (пустой флеш)

```
python bsl_version.py COM16 --inv-rst --inv-test          # проверка связи
python bsl_erase.py COM16 --inv-rst --inv-test --all      # очистить флеш + Info B (опционально)
python bsl_write.py COM16 --inv-rst --inv-test --write-info firmware.bin
python bsl_read.py  COM16 --inv-rst --inv-test --pwfile firmware.bin --dump
python compare.py                                          # независимая сверка
```

Затем полный цикл питания (снять питание, подождать пару секунд, подать) —
чип выйдет из BSL и загрузится с адреса reset-вектора из образа.

### Обновление прошивки на живом чипе

```
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin
```

Пароль берётся из образа (векторы) — ACK с первого раза, без стираний.

### Бэкап перед экспериментами

```
python bsl_read.py COM16 --inv-rst --inv-test --pwfile firmware.bin --dump
```

Сохранит `flash_dump.bin` и `info_a.bin` — можно вернуть в любой момент `bsl_write.py`.

### Дозапись Info без стирания флеша

```
python bsl_write.py COM16 --inv-rst --inv-test --write-info firmware.bin
```

Пароль из векторов даёт ACK без стираний, пустые блоки флеша пропускаются —
прошивка в основном флеше не трогается.

## Архитектура `bsl_core.py`

Все общие функции собраны в ядро, скрипты содержат только уникальную логику.

### Слой Win32 (`ctypes`)

| Функция | Что делает |
|---|---|
| `open_port(name, baud=9600)` | Открытие COM через `CreateFileW`, настройка DCB (9600 8E1) и таймаутов |
| `set_lines(h, dtr, rts, inv_rst, inv_test)` | Установка DTR/RTS с учётом инверсии |
| `flush_in(h)` | `PurgeComm` — очистка входного буфера |
| `write(h, data)` / `write_slow(h, data, gap)` | Запись одним куском или с паузой между байтами |
| `read(h, count, timeout)` | Чтение с дедлайном (никогда не висит вечно) |
| `close_port(h)` | Сброс линий и закрытие порта |

### Слой протокола (легаси-BSL)

| Функция | Команда | Описание |
|---|---|---|
| `xorchk(data)` | — | Контрольная сумма: XOR чётных/нечётных байт с инверсией |
| `frame(cmd, payload)` | — | Сборка фрейма: `80 cmd len len payload chk chk` |
| `sync(h)` | 0x80 | SYNC перед каждой командой, до 5 попыток |
| `enter_bsl(h, inv_rst, inv_test)` | — | Входная последовательность: 2×(TEST пульс) + RST с TEST=1 |
| `send_cmd(h, cmd, payload, gap, timeout)` | — | SYNC → фрейм → ответ (ACK/NAK или заголовок данных) |
| `probe_version(h)` | 0x1E | Чтение версии BSL (BSL 1.61, семейство 0xF1 0x6C) |
| `rx_password(h, pw)` | 0x10 | Отправка пароля (4 байта-заглушки + 32 байта). ACK = разблокировано |
| `tx_data_block(h, addr, n)` | 0x14 | Чтение блока памяти с дедлайном и проверкой контрольной суммы |
| `rx_data_block(h, addr, data)` | 0x12 | Запись блока памяти |
| `mass_erase(h, info_too)` | 0x18 | Mass Erase: 0xA506 (флеш) / 0xA505 (флеш + Info B) |
| `erase_segment(h, addr)` | 0x16 | Стирание одного сегмента (0xA502 — безусловно) |
| `read_range(h, addr, length, gap, label)` | 0x14×N | Чтение диапазона блоками по 128 с прогрессом каждые 16 |
| `load_image(path)` | — | Загрузка образа: `.bin` (должен быть ровно 65536) или Intel HEX |
| `password_candidates(img)` | — | Кандидаты пароля: векторы образа (если непусты), затем `FF`×32 |

Все обмены имеют таймауты — скрипт никогда не висит бесконечно, при сбое
печатает понятное сообщение и завершается.

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| `SYNC/версия не получены` и нет строк DTR/RTS | Не заданы `--inv-rst --inv-test` | Добавьте оба флага |
| Строки DTR/RTS есть, «Ответ: 80», потом ошибка версии | Чип в BSL, но ответ распознан криво | Обновите `bsl_core.py` (исправлено в текущей версии) |
| «BSL version» печатается, но дальше NAK на запись | Пароль не совпал | NAK = mass erase; это нормально, перезапустите запись |
| `Пароль FF не принят` при полностью пустом чипе | Порт занят другим процессом или обвязка не та | Закройте мониторы порта, проверьте подключение |
| Чтение «висит» долго без прогресса | Старая версия без прогресса, или `--gap` велик | Обновите `bsl_core.py` (прогресс каждые 16 блоков), уменьшите `--gap` до 0.01 |
| Записанные блоки не совпадают при проверке | Плохой контакт, помехи, слабое питание | Проверьте питание (BSL требует ~2.7 В минимум), уменьшите скорость канала (`--gap` больше), переподключите провода |
| Векторы не совпали после заливки | Прерванная запись | Перезапустите `bsl_write.py` целиком |
| `CreateFileW` не открывает порт | Порт занят (BSL430.NET, монитор, второй скрипт) | Закройте все программы, использующие COM16 |

Общий принцип: при любых странностях запускайте с `--trace` — построчный лог
показывает, на какой команде оборвался обмен.
