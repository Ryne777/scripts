# MSP430F1611 — реанимация через легаси-BSL

Набор самостоятельных Python-скриптов для работы с BSL (Boot Strap Loader)
MSP430F1611 через самодельный адаптер на CH340T: чтение, запись, стирание
и проверка прошивки. Только стандартная библиотека + `pyserial` для
вспомогательных тестов (сами BSL-скрипты используют Win32 API напрямую).

Требования: Windows, Python 3.8+, COM-порт адаптера (например `COM16`),
скорость обмена 9600, формат 8E1 (чётность — обязательна для легаси-BSL).

## Состав набора

| Файл | Роль |
|---|---|
| `bsl_core.py` | Общий модуль: Win32-обёртки, протокол BSL, вход, пароль, чтение/запись |
| `bsl_version.py` | Быстрая проверка связи: вход в BSL и чтение версии загрузчика |
| `bsl_read.py` | Чтение Info, векторов, полный дамп флеша в файл |
| `bsl_write.py` | Запись прошивки с проверкой каждого блока, запись Info |
| `bsl_erase.py` | Mass Erase / стирание сегментов с верификацией чтением |
| `compare.py` | Побайтовое сравнение дампа чипа с образом прошивки |
| `firmware.bin` | Образ прошивки (64 КБ: 0x0000..0xFFFF) |
| `readme.md` / `README.pdf` | Эта документация |

## Распиновка программатора (CH340T → MSP430F1611, корпус PM64)

| Пин разъёма | Сигнал | Ножка CH340T | Ножка F1611 (PM64) |
|---:|---|---:|---:|
| 1 | RXD (от таргета) | 4 | P1.1 — 13 |
| 2 | TST (RTS#) | 16 | TCK — 57 |
| 3 | TXD (к таргету) | 3 | P2.2 — 22 |
| 4 | RST (DTR#) | 15 | RST/NMI — 58 |
| 5 | GND | 8 | DVSS — 63 (+ AVSS — 62) |
| 6 | VCC 3.3 В | AMS1117 | DVCC — 1 (+ AVCC — 64) |

Пояснения:
- `RTS#` и `DTR#` — инвертированные относительно уровней на ножках CH340T,
  поэтому во всех командах скриптов обязательны флаги `--inv-rst --inv-test`.
- Сигналы TST/RST — входная последовательность BSL: именно они вводят чип
  в загрузчик (см. `enter_bsl` в `bsl_core.py`).
- Питание 3.3 В от AMS1117: не запитывайте таргет от иных источников при
  подключённом адаптере без общей земли.

Программатор полностью готов к работе — теперь чистая практика.

## Общие параметры (все скрипты)

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `port` | — | COM-порт адаптера, например `COM16` |
| `--inv-rst` | выкл | Инверсия RST (DTR) — обязательна для этого адаптера |
| `--inv-test` | выкл | Инверсия TEST (RTS) — обязательна для этого адаптера |
| `--gap SEC` | `0.01` | Пауза между байтами фрейма; на надёжность канала — `0.05` |
| `--slow SEC` | `0.02` | Пауза внутри входной последовательности |
| `--trace` | выкл | Печать уровней DTR/RTS и ответов BSL |
| `--pwfile FILE` | — | Пароль из векторов образа (безопасный вход) |

## Правило паролей (важно!)

- Пароль BSL = содержимое векторов прерываний `0xFFE0..0xFFFF` — 32 байта.
- NAK в ответ на пароль у 1xx-протокола **равен mass erase всей памяти**.
- Поэтому порядок всегда такой: сначала пробуем пароль из образа прошивки
  (`password_candidates` в `bsl_core.py` даёт его первым), и только
  `FF`×32 — для заведомо стёртого чипа.
- Info-сегмент A (0x1000..0x107F, калибровки DCO) защищён: BSL 1.61 его
  не стирает и не отдаёт на запись. Info B (0x1080..0x10FF) — наша забота.

## bsl_version.py — проверка связи

```bash
python bsl_version.py COM16 --inv-rst --inv-test
```

Выполняет вход в BSL, читает версию загрузчика (ожидается `BSL version:
1.61, семейство: 0xF1 0x6C`), выходит. Если версия печатается — канал,
адаптер и вход в BSL исправны.

## bsl_read.py — чтение

```bash
python bsl_read.py COM16 --inv-rst --inv-test --gap 0.05 --pwfile firmware.bin --dump
```

- пароль из `--pwfile` (векторы образа) → ACK без стираний;
- читает Info 0x1000..0x10FF → `info_a.bin`;
- читает векторы 0xFFE0..0xFFFF (контроль против образа);
- с `--dump` читает основной флеш 0x4000..0xFFFF → `flash_dump.bin`
  с прогрессом каждые 16 блоков.

## bsl_write.py — запись

```bash
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin
```

- стирает несовпадающие сегменты, пишет блоками по 128 байт, каждый блок
  перечитывает и сверяет (повторы при сбое);
- финальный контроль векторов против образа;
- `--write-info` — дополнительно записывает Info-область из образа
  (0x1000..0x10FF); при пустой Info-области в образе — пропускает.

## bsl_erase.py — стирание

```bash
python bsl_erase.py COM16 --inv-rst --inv-test            # основной флеш
python bsl_erase.py COM16 --inv-rst --inv-test --all      # флеш + Info B
python bsl_erase.py COM16 --inv-rst --inv-test --segment 0x4000
```

- подтверждение перед стиранием (отключается `--yes`);
- Mass Erase разрешён без пароля; команда 0x18 со словом 0xA506 (флеш)
  или 0xA505 (флеш + Info B);
- NAK после стирания у BSL 1.60+ бывает и при успехе (глюк erase check),
  поэтому истина проверяется чтением: `verify_erased` добивается «все FF»;
- после стирания пароль чипа становится `FF`×32 — заливать заново сразу.

## compare.py — сверка дампа с образом

```bash
python compare.py
```

Сравнивает `flash_dump.bin` с `firmware.bin[0x4000:0x10000]` и
`info_a.bin` с `firmware.bin[0x1000:0x1100]`. Ожидаемый результат:
обе строки «OK — побайтово совпадает».

## Типовые сценарии

### Реанимация стёртого/неизвестного чипа
```bash
python bsl_version.py COM16 --inv-rst --inv-test
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin
python bsl_read.py  COM16 --inv-rst --inv-test --pwfile firmware.bin --dump
python compare.py
```

### Обновление прошивки (чип уже с образом)
```bash
python bsl_erase.py COM16 --inv-rst --inv-test --yes
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin
```

### Бэкап
```bash
python bsl_read.py COM16 --inv-rst --inv-test --gap 0.05 --pwfile firmware.bin --dump
```

### Дозапись Info (без стирания флеша)
```bash
python bsl_write.py COM16 --inv-rst --inv-test firmware.bin --write-info
```

## Архитектура bsl_core.py

Слой Win32: `open_port` (9600 8E1, таймауты), `set_lines` (DTR/RTS с
инверсией), `flush_in`, `write`, `write_slow`, `read`, `close_port`.

Слой протокола (команды легаси-BSL):

| Команда | Код | Назначение |
|---|---:|---|
| RX Password | `0x10` | Разблокировка (NAK = mass erase!) |
| RX Data Block | `0x12` | Запись блока |
| TX Data Block | `0x14` | Чтение блока |
| Erase Segment | `0x16` | Стирание сегмента (0xA502 — безусловно) |
| Mass Erase | `0x18` | Стирание флеша (0xA506) / флеш+Info B (0xA505) |
| BSL Version | `0x1E` | Версия загрузчика |

Плюс: `xorchk`, `frame`, `sync`, `enter_bsl`, `send_cmd`, `probe_version`,
`tx_data_block`, `rx_data_block`, `rx_password`, `password_candidates`,
`load_image` (bin + Intel HEX), `read_range` (с прогрессом), `mass_erase`,
`erase_segment`, `verify_erased`.

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| «SYNC не получены» без строк DTR/RTS | Не заданы инверсии | Добавить `--inv-rst --inv-test` |
| «SYNC/версия не получены», но «Ответ: 80» есть | Баг чтения версии (старые версии erase-скрипта) | Обновить `bsl_core.py` — `probe_version` исправлен |
| Порт не открывается | Занят другим клиентом COM-порта | Закрыть второй клиент COM |
| NAK на пароль из образа | Векторы образа ≠ пароль чипа | Сверить `0xFFE0..0xFFFF`; NAK = стёрся флеш |
| «Не стёрто» в верификации | Сбой канала на длинных фреймах | Перестирать, увеличить `--gap` |
| Печатает мусор / «кривые тайминги» после запуска | Пустые калибровки Info B | Перезапись с `--write-info` |

## Рекомендации по архиву

Хранить в одном месте: `bsl_core.py`, четыре скрипта, `compare.py`,
`firmware.bin`, последний дамп, `README.pdf`. Следующая реанимация —
пять минут: проверить связь → записать → сверить.
